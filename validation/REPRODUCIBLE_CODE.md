# Python syntax: capability and verification boundaries

The inventory in `REPRODUCIBLE_ANALYSIS_INVENTORY.json` is generated by
`python tools/inventory_reproducible.py`. It covers app, UI and standalone
missing-data screens. An imported name is not evidence of an implemented analysis.
No separate covariance-based CFA or regression screen was found; no such analysis
is invented by the generator. Multidimensional IRT CFA is not lavaan SEM.

## Current coverage

All existing screens receive the shared syntax panel. Public calculation calls
from loaded `core` modules are recorded at their actual input boundary; deferred
UI imports are instrumented before rendering. Python replays existing APIs,
including KTK, reliability, dimensionality/PAF, local fit, all existing IRT/MIRT
and DIF paths and missing-data analysis **when their actual arguments can be
faithfully serialized**. Unsupported categorical dtypes, opaque objects without
producer provenance, or other unmapped inputs suppress code rather than guessing.
The 3PL/4PL bootstrap-DIF core is explicitly UNSUPPORTED for code export until its UI-only inference gate can be reproduced; raw p-values suppressed by the UI are never exported through a replay script.
Cached opaque outcomes are replayable only when their actual producer was
recorded in the preceding same-page run. Otherwise the panel says UNSUPPORTED.

Independent R scientific comparisons remain separate from user-facing Python code generation. Their reference scripts, model validations and CI workflows are preserved.

## Data and portability

Scripts embed exact selected data, indices, labels, missingness and all bound
API arguments/defaults, including seeds when explicitly present. Data already
filtered/recoded by the UI is preserved **after** those operations; unknown raw
preparation history is explicitly UNAVAILABLE. It is not guessed or reapplied.
A 250000-cell per-object export memory guard marks oversized inputs UNSUPPORTED
without changing the analysis. JSON preserves floating values and dtype metadata; unsupported mappings fail
closed. Scripts/ZIP downloads contain user data and are generated locally.

Python uses a bundled offline copy of existing core/report sources, requirements,
recorded package/Python versions and SHA256 checks. A `.py` copied without the
ZIP can fetch the public calculation source at the recorded immutable commit;
no data is transmitted. No packages install automatically. The only new Python
calculation is serialization/replay; no psychometric estimator is implemented.
Download buttons do not rerun calibrations. Streamlit's code
block supplies copy/highlighting. Each rerun records current actual calls;
previous results are never inferred from a page or model name alone.

## Status and tests

GENERATED / UNVERIFIED is the default, per actual input/settings. Executing the
original application does not verify generated code. VERIFIED requires actual
execution of the generated Python script **for the same inputs** and basic
result comparison; no user-specific VERIFIED claim is currently issued.
UNSUPPORTED means no faithful whole-analysis Python script is available. Code generation
and deterministic parity tests never imply scientific model certification.

Targeted tests execute a portable Python bundle outside the repository, compare
actual descriptive outputs, verify data-value changes, unknown mappings, argument
binding, cached provenance, isolation, inventory and Streamlit controls. Independent base-R
reference execution/parity runs in the existing tests workflow using R 4.6.1; missing R is a
failure there, not a skipped scientific check. Locally unavailable R is reported
NOT EXECUTED. The fixed reference in `validation/descriptive_reference.R` is test-only and never included in user downloads. No IRT/R calibration or prior validation study is repeated.
